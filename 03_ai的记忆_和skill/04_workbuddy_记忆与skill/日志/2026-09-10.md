### 做对的 ✅
- 在 VM 克隆 xone 源码（`~/tmp/xone`），确认其 `wired.c` 设备表含 `XONE_WIRED_VENDOR(0x1532)` → 自带雷蛇 GIP 支持，不用改 PID
- 定位真实编译树：xpad.o 来自 `kernel_platform/common/`（GKI），不是 `msm-kernel`。两棵树都有 xpad.c，common 才是 GKI 编译源
- 内核是 **5.15.170**（不是 6.1），`USB_ARCH_HAS_HCD` 仍存在，`CONFIG_JOYSTICK_XPAD_FF=y` 已启用
- 用 python3 脚本精确插入 `xone_claim_needed()` + xpad_probe 让路（`return -ENODEV`），避开了 sed 引号地狱
- 把 xone 7 个 .c + Kconfig + Makefile 拷进 common + msm-kernel 两棵树的 `drivers/input/joystick/xone/`
- 在 `kalama_GKI.config` 同时写了 `JOYSTICK_XONE_WIRED=y` + `INPUT_FF_MEMLESS=y` + CRYPTO_ECDSA/ECDH/SHA256/ECC/HMAC=y
- 两份 xpad.c 都打了让路补丁（common + msm-kernel）

### 做错的 / 踩的坑 ⚠️
- **相对路径自杀**：`cd kernel_platform` 后又用 `kernel_platform/...` 造出嵌套假目录 `kernel_platform/kernel_platform/...`，文件拷错地方。教训：进入目录后只用相对路径或绝对变量
- **heredoc + $() 冲突**：bash 把 `$(CONFIG_...)`、括号 `()` 当变量/语法展开，Kconfig/Makefile 写入全空。教训：含 `$(` 或 `()` 的内容一律写本地文件 scp 上去，或用 `/tmp` 中转
- **sed 截取文件**：`head --1` 报错导致 xpad.c 被截断到 3 行，靠 `/tmp/xpad.c.bak` 恢复。教训：编辑前先 cp 备份，用 python 而非 sed 拼文件
- **config 检测误判**：`grep -q 'XONE' && skip` 在已有 XONE 行时整块跳过，crypto 没写进去。补了二次追加才补齐
- **未验证编译**：尝试 out-of-tree 编译 `wired.o` 失败（缺 `.config` + clang 不在 PATH），没真正验证过 5.15 API 兼容性。这是最大未决项
