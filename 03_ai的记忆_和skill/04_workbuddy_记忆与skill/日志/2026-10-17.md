## 一、方案层：用户连着三次改口，每次都带动排期

1. **网络从"网线"改成 WiFi**（用户："所以我们是要用 wifi 的"）。
   我先去查了 JetKVM 自己怎么做（读 `jetkvm/kvm` 源码）：**原版是纯有线** —— `network.go` 写死
   `const NetIfName = "eth0"`，`getDeviceCapabilities()` 的能力表里**没有 `wifi`**，全仓库**蓝牙 0 命中**。
   但用户场景是"板子贴着被控机放、路由器口不一定够"，所以**反过来选 WiFi**，网线降为调试备胎。
   代价写进文档：要还 Q8.1–Q8.5 五笔债（电台频段/工具链/首配通道/固定地址/实测吞吐），
   并且 **P1.5（ACM 控制台）从"顺手"升级成"必须"** —— 否则 WiFi 配错一次就把自已锁在门外。
2. **去掉采集棒**（用户："再把采集棒这个去掉 变成刷带时间戳的帧不就解决了吗"）。
   定成三档：假源 → **被控机 agent 推屏** → 采集棒（按需）。关键论证记进记忆：
   **档 2 能覆盖的场合，恰好是不需要 KVM 的场合**（那时用 RustDesk 就行）；KVM 的价值在档 2 瞎掉的时刻。
3. **目标收缩**（用户："被控电脑不用搞这些 就是开着的 windows"、"你先别装怪东西，我们先把板子调试好"）。
   ⇒ 被控机 = **用户这台 Windows 笔记本**；现阶段在被控机上**唯一动作是插一根线**；
   P5（agent）、Q13/Q14/Q15 全部挂起，Q16（黑帧）因笔记本自带屏直接关闭，Q17（安全）用户明确"不管"。
   最终硬件清单：**板子 + 原装电源 + 一根 USB-C→A 线 + 一个 WiFi，一个新件都不买。**

## 二、P1：开 HID gadget（10-16 做完，10-17 上板）

- 🔴 **改内核 config 必须改 defconfig，改 `.config` 会被无声覆盖**：
  `device/rockchip/common/scripts/mk-kernel.sh` 的 `do_make_kernel_config()` 每次构建都跑
  `make $RK_KERNEL_CFG`（本机 = `kernel-6.1/arch/arm64/configs/rockchip_linux_defconfig`）重新生成 `.config`。
  板级 defconfig（`device/rockchip/.chips/rk3566_rk3568/rockchip_rk3566_kickpi_k11c_v12_ubuntu_defconfig`）
  只管 DTS/rootfs/parameter，**不含内核 config**。
- 要开的选项名字是 **`CONFIG_USB_CONFIGFS_F_HID`**（不是 `USB_CONFIGFS_HID`），它 select `USB_F_HID`。
  官方 defconfig 里有 ACM/MASS_STORAGE/F_FS/F_UVC，**独独没有 F_HID**。
- `./build.sh xxx` 在非交互 ssh 里会**直接失败**：它有一段 `read -s "[sudo] password"`（给 mount/losetup 缓存口令），
  没 tty 就 exit 1。绕法见 skill `vm-ssh-sudo-exec`：自己导出 `SUDO_ASKPASS` + `sudo -A` 的 PATH 包装，
  让它 `if [ -z "$SUDO_ASKPASS" ]` 那整段跳过。
- **Q2 没花一次烧写去"试"，是读源码 + 读编译出的 DTB 定案的**：
  `dtc -I dtb -O dts` 看实际进板子的 DTB → `usb@fcc00000` 是 `status=okay` + `dr_mode=otg`，
  **全 DTB 里 `usb-role-switch` 出现 0 次、也没有 `extcon`**；再看 `dwc3_drd_init()`：
  两者都没有 ⇒ 落到 `else` 分支 = **靠 ID 引脚猜角色**，而本板 Type-C 没有 CC 控制器。
  ⇒ 在 `rk3566-kickpi-k11c-v12.dtsi` 末尾写死 `&usbdrd_dwc3 { dr_mode = "peripheral"; }`。
  `core.c` 里 `USB_DR_MODE_PERIPHERAL` 是**无条件 `dwc3_gadget_init()`**，所以这是把 50/50 变 100%。
- 全量 diff 就 **2 个文件 8 行**。产物 `update.img` 7,172,541,002 B，md5 `51b7a9ab3cc9a752022090ed480e6c18`。
  ⚠️ 别拿 update.img 大小当"改到位"的证据（分区对齐）—— 看 md5 + 直接查 DTB。

## 三、P1.5 + P2：上板实测，判定通过（10-17 晚）

**结果（都是量出来的）**

| 项 | 结果 |
|---|---|
| UDC | `fcc00000.usb` 存在，运行时 DT `dr_mode=peripheral` 生效 |
| Windows 枚举 | `USB\VID_1D6B&PID_0104` → `MI_00 HID Keyboard Device` / `MI_01 HID-compliant mouse` / `MI_02 USB Serial Port (COM15)` |
| 键盘打字 | 板子发字 → `Ctrl+A` `Ctrl+C` → Windows `Get-Clipboard` 读回 **`HELLO NZS`**，逐字符正确 |
| 绝对鼠标 | 光标 `1281,162` → **`959,539`**（发 `(0.5,0.5)`，1920×1080 正中） |
| ACM | **COM15** 出现 = 不依赖网络的自救控制台（比 1500000 的 COM14 好太多） |

**🔴 四个坑（每个都能白耗半天）**

1. **沿用官方 `VID_2207&PID_0006` 会让 HID 接口"人间蒸发"** —— Windows 装过的 Android 驱动按**硬件 ID**
   把复合设备的**父节点整台认领**，连 `MI_` 子设备都不生成，看起来像我们描述符写坏了。
   排查特征：`Get-PnpDevice -PresentOnly` 里只有 `AndroidUsbDeviceClass`、**没有任何 `MI_xx`**。
   ⇒ 必须自己的 VID/PID（实测 `1d6b:0104` 可用）+ `bDeviceClass=EF/02/01`。
2. **gadget 已绑 UDC 时 configfs 拒绝把 function 链进 config（EBUSY）**，而我第一版脚本给 `ln -s` 加了 `|| true`
   **把错误吞了** ⇒ 出现"六个 function 都建好了、config 里只有 adb"的诡异现象。
   ⇒ 顺序必须 **解绑 → 建 function + 链进 config → 再绑**；**永远别吞 `ln -s` 的错误**。
3. **SDK 的 6.1 内核 hid function 没有 `wakeup_on_write`**（那是 JetKVM 5.10 的厂改属性）→ 写它 `Permission denied`。
   可用属性只有：`dev(ro) no_out_endpoint protocol report_desc report_length subclass`。
4. **换 gadget 会杀死 adb，而 adbd 一死会把它派生的脚本一起带走**（`setsid nohup` 也没扛住）
   ⇒ 用 **`systemd-run --collect`** 丢给 PID1 跑。
   附带：`adb push` 的远端路径会被 Git Bash 改写成 `C:/Program Files/Git/...` ⇒ 加 `MSYS_NO_PATHCONV=1`，
   源路径写 Windows 式、目标路径写 `/tmp/...`。

**🟡 一个必须做进前端的使用层问题**：被控机开着**中文输入法**时，我们发的字母会被**吃进 IME 候选框**、不进文档，
表现极像"键盘坏了"（但 CapsLock 照样生效，因为 IME 不拦它）。板子发 `Ctrl+Space` 切英文后立刻正常。
⇒ P4 控制页必须处理输入法（JetKVM 的做法是 `setKeyboardLayout` + 文本粘贴通道）。

**测试方法学（下次直接抄）**：验证"字真的进了系统"不要靠人眼看 ——
开记事本/Notepad++ → 板子打字 → 板子发 `Ctrl+A`+`Ctrl+C` → PowerShell `Get-Clipboard` 读回比对。
PowerShell 一律写成临时 `.ps1` 再执行，别在 bash 里内嵌 `$_`/`$()`（会被 bash 吃掉）。

## 四、烘进固件（P2hid-noadb 版）

- rootfs 内容目录是 `ubuntu/binary/`（5.4G 完整树，root 属主），`ubuntu/mk-image.sh` 本质就是
  `mkfs.ext4 -d binary ubuntu-rootfs.img <SIZE>M`，SIZE = `du --apparent-size -sm` + `文件数*4/1024 + 64`，再 +10%。
  我**手动跑 mk-image 的等价命令**，避开 `build.sh ubuntu` 的 overlay 分支不确定性。
- 装进去的东西：`/usr/local/sbin/k11c-gadget.sh`、`/etc/systemd/system/k11c-gadget.service` +
  `multi-user.target.wants` 软链（开机自启）、`/root/k11c/{k11c_hid.py,k11cd.py}`，
  并 **`/etc/systemd/system/usb-gadget.service → /dev/null`（mask 掉官方 adb gadget —— 就是它占着 UDC）**。
- 产物：`D:\02_baidu\自建镜像\K11C_v12_ubuntu2404_selfbuild-P2hid-noadb-20261017.img`
  7,172,541,002 B，md5 **`467b9973a4804a5944955ff8128f9daa`**（VM/Windows 两端核对一致）。
- ⚠️ 这版**没有 adb**（主动换掉的）。退回：刷 `...-P1hid-peripheral-20261016.img`，
  或板子上 `systemctl unmask usb-gadget && systemctl start usb-gadget`。
