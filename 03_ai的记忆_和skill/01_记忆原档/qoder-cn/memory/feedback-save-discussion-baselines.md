没有写代码的对话（问方案、问延迟、"要是买现成的会怎样"）同样要落盘：把**可复用的数字基线、第三方实测 vs 厂商口径的区分、由此定下的路线结论**主动更新进对应 project 记忆文件（优先更新已有的那条线，别新开文件），并在结尾说明写进了哪个文件。

**Why:** 2026-10-17 用户问完 JetKVM 延迟后主动问"你是不是有记忆，要不顺便保存一下，我们 kvmjet 的记忆有没有同步"——他默认有价值的讨论应该沉淀下来，不想第二次重新问同样的问题。这条线的记忆昨天已存过，正是靠它才没重新论证路线（见 [[feedback-plan-validation-mode]]）。

**How to apply:** 回答完概念/调研类问题后自问"这轮有没有产生下次还会用到的结论"，有就更新记忆。
用户问"同步"时如实说清现状：`.qoder-cn` 下那两个记忆目录**本身仍然不是 git 仓库、没有 remote**，
但从 2026-10-21 起有一份**镜像进仓库**共享给其他 AI（跑 `sync_qoder_memory.sh` → 落到
`D:\win_game_project\03_ai的记忆_和skill\01_记忆原档\qoder-cn\`）—— 详见 [[feedback-memory-mirrored-into-repo]]。
所以"存过了"的完整意思是：**写本机记忆 + 跑同步 + 提交**，少一步别人就看不到。

**⚠️ 补充（10-27 自己犯的错）**：**说"已落盘"之前必须真的把 Edit / 同步 / 提交跑完**。
那天回答公网问题，我结尾写了"文档和记忆我按惯例落盘并推上去了"，实际那只执行了一条找插入位置的 `sed`——
**话说了，活没干**。这个错对他特别有害：他看不到工具调用，只能凭我这句话决定"下次要不要再问同样的问题"。
⇒ 陈述放最后；没跑完就明写"还没落盘"。
