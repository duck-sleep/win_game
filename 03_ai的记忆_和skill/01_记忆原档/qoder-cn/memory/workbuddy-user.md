# WorkBuddy 用户资料

- **City:** 两地跑 —— 有时香港，有时深圳
- **技术底子（2026-10-15 观察）：** Linux 功底扎实（会看 `ifconfig`/`ss`/sysfs、自己在 VM 里操作），
  主线是 Android BSP / 高通 AOSP 编译与刷机等**内核+系统集成**层面的活。
  但**嵌入式"造文件系统"那套工具链不熟** —— 2026-10-15 明确问"buildroot 是啥系统，我没听过"。
  讲这类东西时拿他熟的坐标系类比（发行版 vs 构建工具、apt 有无、有没有桌面），别当行话直接抛名词。
- **硬件版本这类事他会自己去主板上看丝印**，问到就直说要看什么，他能立刻给你答案。
- **知识地图（2026-10-21 明确暴露，讲东西按这个分深浅）**：
  - 🟢 **强**：硬件视频管线（海思 `VI/VPSS/VENC` 那套他熟）、设备树/内核配置、SDK 编译烧录、USB 电气与枚举、
    自己会拿示波器/看丝印。硬编"不是我教他的，是他本来就知道"。
  - 🔴 **不在他栈里**（他自己原话："**这个玩意就碰到我技术栈不会了**"）：WebRTC / HTTP / datachannel / SDP / ICE 这套网络栈，
    以及 **Git 与 GitHub 的运作方式**（问过"仓库是什么东西"、"为什么是照着设计而不是直接移植"、
    分不清 `ubuntu-rootfs.img` 和 SDK 的关系、以为"烧固件=打开硬编"）。
  - ⇒ **讲这些一律先用他的坐标系类比**：HTTP 请求-应答 ≈ Modbus 主从轮询；datachannel ≈ SPI 全双工推出去就走；
    报文/通道 ≈ 协议层 vs 实现层；rootfs.img ≈ 文件系统本体、SDK 源码树 ≈ 造它的全套工具+源码。
    **别默认他懂 commit/push/仓库/镜像分层这些词**，说了就要展开；他问"是什么东西"是要真解释，不是客套。
- **他要"为什么"不只"是什么"**：会追问"为什么这部分是照着设计而不是直接移植"、"SDK 的修改不止这么点吧"。
  ⇒ 给结论时**主动带上判断依据和被否掉的可能**。
- **沟通语言：中文。** 文档也写中文。
