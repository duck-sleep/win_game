The root cause was that all four modes shared a single global band gain configuration, with only threshold/gamma/transient parameters changing. The fix involved adding per-mode gain presets (MODE_BAND_GAINS) in analyzer.py, modifying pipeline.py to load the corresponding mode's gains when switching, updating app.py to refresh the canvas display, and implementing persistence in config_store.py. Now each mode has independent gain curves (e.g., 70/50/20% for controlled, 100/70/30% for balanced), with user adjustments saved per mode and retained after restarts. The user needs to restart HapticX via 启动HapticX.bat for changes to take effect.

The assistant explained six key parameter stations in plain language with analogies: ① Sampling (48kHz, 20ms processing cycle) - how sound enters the system; ② FFT Window (50ms) - decomposing sound into frequencies; ③ Frequency Selection (30-130Hz with EQ curve) - filtering vibration-sensitive frequencies; ④ Strength Calculation (40ms amplitude window, 125ms frequency window) - averaging sound intensity; ⑤ Intensity Control (threshold 0.03, gamma 3, gain 0.67) - compressing volume range; ⑥ Beat Detection (22ms transient duration, prominence 0.4, volume 0.25/0.35/0.6 for modes) - making vibration follow beats. It clarified that parameters in stations ①-⑤ are copied from Synapse logs, while station ⑥'s mode differences (transient volume and frequency band gains) are designed based on user feedback. The user requested adding this plain-language explanation to the document.
