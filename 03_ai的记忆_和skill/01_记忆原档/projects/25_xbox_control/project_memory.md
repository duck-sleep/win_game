## 做完了什么

产品路径是「按供应商抄」：WASAPI 环回 → `a2h_encoder.py` → `har_pack.py` → 滑条只乘一次 → `ihhe.wrap_feature4` → COL04 `HidD_SetFeature`。不加载雷云 DLL。

对着 `RzInterhapticsHapticEncoder` v2.0.1.11 抄。验收只认同一段 PCM 逐帧对照，不认听感。

2026-10-13 重跑，编码器出口（不乘滑条、不走 USB）全部 0 帧不同：

- 17 行纯音：两条曲线和瞬态 17/17 相同
- 60 Hz 0.40：0/25；60 Hz 0.80：0/20
- 每秒 4 下敲击（60 Hz、0.85、每下 40 ms）：0/50
- 40–180 Hz 扫频、幅度 0.4：0/50
- 左右不同三段（左响右静音、左静音右响、左 60 Hz 右 150 Hz）：各 0/20

## 最后修的两处

1. 瞬态参考值。`FUN_18001f670` 在 `0x18001FCCA` 每个谷都把参考值改成这个谷，不管记没记成瞬态。漏了这个，380 ms 和 880 ms 两帧会少一条 `(54, 0, 0)`。已改。
2. 立体声。DLL 的 `FUN_18001ef60` 让 216 用左声道、116 用右声道，各自扫瞬态、各自 FFT。修之前瞬态只扫左声道并复制，音高两只手共用。已改。

## 听感

用户听过「一跳一跳」。逐帧对照不能把它归到某一步。离线每块大约 13 ms，三次里超过 20 ms 的块是至少 1、0、6（各 240 块），最长 51.7 ms。这是不开界面、不发 HID 量的。

## 滑条

雷云日志是 `SetHapticMixerGain(67)`，只乘一次 0.67。收口时 `hapticx/config.json` 的 `gain` 是 1.0。100% 会比雷云 67% 重，这是旋钮，不是第二套算法。
