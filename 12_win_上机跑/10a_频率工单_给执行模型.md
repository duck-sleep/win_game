## 2026-09-17 阶段总结（下一会话先读）

### 一句话

雷云 SENSA 把音高收成有限档，经 HID Feature 报告 4（91 字节、约 20ms）发给 `0a4c`。我们能把抓到的包原样写回去（USB 已对上）。这不是实时听音复刻，也还没人手确认马达在唱。振幅字段未拆出。W3B.8 的 Hz 直线/插值已失败，不要再拟合 `b12=a×f+b`。

### 已经成立（有证据）

| 项 | 结论 |
|----|------|
| 运输 | Control SET_REPORT，Feature ID 4，91 字节，endpoint 0，wIndex=1，约 20ms |
| 写回接口 | `HID\VID_1532&PID_0A4C&MI_01&COL04`，`HidD_SetFeature` / `GetFeature` 可开 |
| 交叉验证 | F50/F110/zero 五轮回读 15/15；STAR 回放 3×232 包成功；写回时再抓 USB 与原 STAR **232/232** 相同 |
| 音高档 | 索引看 **b15（偶数）**；`b12 ≈ (4*b15+2) mod 256`（±1 抖）。C3 时 b12 绕成 8–12 |
| 量化 | E2 与 80Hz 同档；F2 与 90Hz 同档；G2 与 100Hz 同档；85Hz 在两档间跳 |
| XInput | Interrupt 8 字节 `00 08 00 LL RR …`，只有转速，不是这条 Feature |
| 官方 API | Interhaptics 能调，但 Sensa Provider **不认** 这只 0a4c；GameInput 在 |

哆来咪码本（等响 RMS 0.20）：C2→b15=22，D2=30，E2=34，F2=38，G2=46，A2=54，B2=62，C3=66。

发音高 ≠ 只改 3 个字节：要循环发送**该档抓到的整包**（约 125ms 换一帧，USB 重复 5–6 次）。同音的正弦和小星星档对得上，包体不是比特级同一张光盘。

### 和雷云的关系

出口同类（同一条 Feature 4、同一套档）。入口不同：雷云是听音+压缩+3 频段编码；我们是查表回放存货。同一纯音在这只垫上会落到差不多同一档，不等于算法已复刻。

## 给执行模型的排错（先对号，再动手）

| 现象 | 先做 |
|------|------|
| probe 没有 A2H | 用户开雷云放音乐，重跑 W0.2，不改正则 |
| test_freq_hz 音符分不开 | 确认用了独立 6000 点估频窗+峰插值；50ms/2400点不够 |
| GUI 无 F | 查 pipeline state 键名是否与 app 一致 |
| USBPcap 列表空 | 重启；禁止 pcap_setup.ps1 |
| pcap 只有几 KB | 换 USBPcap 编号；确认手柄在这棵 USB 树 |
| tshark txt 空 | 查该 pcap 的 bus/device address 是否重枚举变化；OUT 固定 direction=0 |
| F50 与 F110 hex 全同 | 结合 3×3；禁止发明显式 Hz 字段 |
| hid 枚举不到目标接口 | 可能目标是 GIP/vendor interface，不要硬装 hidapi |
| 适配器发出不震 | 回官方路由/字节地图/驱动占用，不要改 analyzer |
| pitch 变化只表现为强弱 | W4.4 判失败；不能宣称频率控制成功 |
