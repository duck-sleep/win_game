## 8. 编译后 git status 显示大量 deleted 是正常现象(重要)

跑过一次编译后,`git status` 会在 VENDOR 仓显示 30 来个文件被删
(全是 `kernel_platform/**/Android.mk` 和 `Android.bp`,如 prebuilts/clang、external/dtc、
greybus、mkbootimg 等)。

**这不是误删,是编译脚本的设计行为。** `kernel_platform/build/android/prepare_vendor.sh`
第 421 行会在每次编译 target 阶段执行:

```bash
find ${ROOT_DIR} \( -name Android.mk -o -name Android.bp \) \
    -a -not -path ${ROOT_DIR}/common/Android.bp -a -not -path ${ROOT_DIR}/msm-kernel/Android.bp \
    -delete
```

原因(脚本官方注释):kernel_platform 里自带的 clang/gcc 预编译工程与 Android 树里的是
同一套,两边的 Android.mk/bp 会冲突,所以编译时统一删掉 kernel_platform 下的这类文件。

**处理原则:**
- 看到这些 deleted 不用管,**每编译一次都会重新出现**
- 提交代码前用 `git status` 过一眼,**不要把这批删除 commit 进去**(会破坏仓库)
- 若它们挡住了 merge(提示 would be overwritten),先 `git checkout -- .` 恢复再合并
- 想要干净的工作区状态:`git checkout -- .` 恢复即可(编译完不需要它们)
