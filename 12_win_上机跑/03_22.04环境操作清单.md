## 第四步：编译（同事的方式）

> 不需要 source envsetup / lunch / export PATH，脚本自己全搞定。
> 建议在 VM 终端跑，不要在 TRAE 沙盒终端跑。

```bash
cd /home/laide/Desktop/10_code/LA.VENDOR.15.4.3    # 注意走符号链接，不带 -irix

tmux new -s build
nice -n 19 ./SNM970_A15_build.sh userdebug kalama 01 2>&1 | tee build.log
```

- `nice -n 19` = 编译进程最低优先级：**操作 TRAE 时内核自动让 CPU 给 TRAE，挂机时编译照样吃满 6 核**，make/ninja/clang 全部继承
- 退出后台：`Ctrl+B` 再按 `D`；重新接回：`tmux attach -t build`
- 预计 6~8 小时（-j6；旧 -j3 时代约 12 小时）
- 产物：`vendor/vendorcode/build/SNM970_userdebug_01.zip` 等
- 万一卡到桌面无响应（基本不会）：`Ctrl+Alt+F3` 切字符终端处理

### 为什么是 -j6（而不是 j3/j4/j5/j32）

| 参数 | 结论 | 理由 |
|------|------|------|
| -j3 | ❌ 淘汰 | 是 21G 内存 + 44G swap 时代的保命值，现在没必要 |
| -j4 / -j5 | 备选 | TRAE 重度使用仍卡时降级用（留核给桌面） |
| **-j6** | ✅ 默认 | 6 vCPU 全部利用，配 `nice -n 19` 后 TRAE 需要时内核自动让 CPU，挂机时编译吃满 6 核 |
| -j32 | ❌ | 同事服务器的配置，6 核机器跑不动 |

> 内存方面：**QSSI 阶段 soong_build 实测需要 40GB+（2026-08-23 首次编译被杀时已吃 37.2GB 仍在增长）**，43G 物理内存不够，已补 48G swap（合计 49G swap，已写 fstab）。-j6 编译阶段（clang 并发）内存无压力。
> TRAE 卡顿超预期时：不必停编译，`renice -n 19 -p $(pgrep -d' ' clang)` 把正在跑的进程也压低即可。

## 第五步：报错预案（按需恢复，不要预防性修改）

> 恢复原始源码后，旧环境踩过的坑**可能**在 22.04 + 完整依赖下自然消失（同事能直接编过），也可能复现。
> 原则：**报什么错恢复什么 workaround**，恢复命令都在下方附录。

| 编译报错 | 恢复动作 | 附录 |
|----------|----------|------|
| `diff: Unknown option 'F'` / `check_current_api FAILED` | 替换 GNU diff（4 处 cp） | A1 |
| `module already defined` | 重命名 kernel_platform 下冲突 Android.bp 为 .bak | A2 |
| `mv: ... resources.arsc: No such file` | Android.bp 去掉 unzip 的 `-x`（两个仓库） | A3 |
| check 规则反复失败 | build.sh 各 make 前 export DISABLE_STUB_VALIDATION | A4 |
| `ld.lld: unable to find -luuid` | uuid-dev 没装对，重跑第二步验证 | — |
| `python2: command not found` | python2 软链没建，重跑 2.2 | — |
| `libtinfo.so.5: cannot open` | 软链没建，重跑 2.3 | — |
| `Killed` / OOM（`dmesg | grep -i oom` 确认） | **soong 阶段 OOM 与 -j 无关**（soong_build 是单进程大内存，QSSI 需 40G+）：确认 swap ≥48G（`free -h`），不够就再加；若 -j6 的 clang 并发阶段 OOM 才降 -j4 | — |
| `ninja: 'device/qcom/kalama-kernel/Image' missing` | toybox 被污染，`git checkout` 恢复 | — |
| `BP_INCLUSION: No such file` | 正常 warning，忽略不用管 | — |
| `wget ... timeout`（FTP 不可达） | FTP 已注释，确认没被 reset 还原 | — |
| `soong bootstrap failed: signal: killed` | OOM 的一种表现，按 OOM 行处理 | — |
| 磁盘满 | 扩容没成功，回第一步检查 | — |
