## 一、这是个什么项目

我们在给一款**安卓复古游戏掌机**做系统固件（Android BSP）的定制、编译和维护。

- **产品型号**：SNM970（产品线对外叫 OK700，Meig 定制，小悠娱乐项目）
- **主控**：Qualcomm QCS8550，高通内部代号 **kalama** —— 所以代码里 lunch 目标、编译参数、设备目录全是 `kalama`
- **系统**：Android 15（内核 6.1 GKI），另支持 Rocknix Linux 双系统
- **用途**：跑模拟器（PS2/PSP/GC/Wii/NDS 等）、串流（Steam/Moonlight）、安卓原生游戏；游戏前端界面由预装的 `ok-frontend.apk`（OnionKnight）提供

硬件概览（详见 `01_资料/文档/OK700 spec.md`）：8 核 Kryo CPU / Adreno 740 GPU / LPDDR5 8G / UFS 3.1 + M.2 SSD 扩展 / 7" OLED 触摸屏 / 掌机按键摇杆（TMR 摇杆×2、ABXY、线性扳机）/ 8000mAh 电池。

## 七、刷机后恢复速查（adb 命令）

> 刷机/重启后设备常处于"初始化向导未完成"状态：**Settings 打不开、解锁页面点不动**。
> 根因是 provision 标志没置上，用 adb 手动补齐即可。

### 1. 出厂设置标志（让 Settings 能打开）—— 每次刷机后必做

```bash
adb shell settings put global device_provisioned 1
adb shell settings put secure user_setup_complete 1

# 验证（两个都应返回 1）
adb shell settings get global device_provisioned
adb shell settings get secure user_setup_complete
```

### 2. IRIX 桌面（gamenative）弹窗抢前台、force-stop 复活时

```bash
adb shell pm disable-user --user 0 app.gamenative   # 禁用，露出 launcher3
adb shell pm enable app.gamenative                  # 恢复
```

### 3. 息屏太快影响操作时

```bash
adb shell svc power stayon true
adb shell settings put system screen_off_timeout 600000
```

### 4. WiFi 掉线重连（SSID 用**纯英文**，中文名板子收不到 beacon 会卡死）

```bash
# 板子自带的 WiFi 路由器，SSID 已改成纯英文「Duck / Duck_5G」（密码 00000000）
# 重连（已保存过，网络 id 还在）：
adb shell cmd wifi connect-network Duck wpa2 00000000

# 若网络未保存，先 add 再连（2.4G 和 5G 都存上，避免 5G 穿墙掉线）：
adb shell cmd wifi add-network Duck wpa2 00000000
adb shell cmd wifi add-network Duck_5G wpa2 00000000
```

> ⚠️ 关键教训（2026-09-07）：原来的中文 SSID「今天鸭鸭还好困」会导致板子
> wlan0 永远 `NO-CARRIER`、supplicant DISCONNECTED、扫描不到自家 AP——
> 高通 WiFi 栈对中文 SSID 的 beacon 匹配有缺陷。**SSID 必须用纯英文/数字**。
> 已保存过的网络直接重连即可；密码仍是 `00000000`。

```bash
# 查扫描结果确认 AP 在不在范围内（开热点后强制刷一轮）
adb shell cmd wifi start-scan
adb shell cmd wifi list-scan-results
```

### 5. WiFi adb 连接（插 USB 的情况下先开 TCP 端口，再拔线）

```bash
# 设备端开 adb TCP 监听（5377 也可，任选）
adb tcpip 5555

# 查设备拿到的 IP（连上 WiFi 后）
adb shell ip addr show wlan0        # 看 inet 那行

# 电脑端连接（IP 换成上一步查到的）★ 这步不能漏！
adb connect 192.168.137.xxx:5555

# 验证（应看到 IP:5555 device）
adb devices

# 断开
adb disconnect 192.168.137.xxx:5555
```

> 顺序很重要：USB 线插着 → `adb tcpip 5555` → 确认 WiFi 已连 → 拔线 → `adb connect`。
> WiFi adb 通了以后才能把 OTG 口让给 hub/手柄收发器（OTG 和 adb 电脑连接不能同时用）。

### 6. 切 OTG host 模式（插 hub + 2.4G 手柄收发器）

```bash
# 切到 host 模式（OTG 口供电 + 枚举外设）
adb shell "echo host > /sys/class/typec/port0/data_role"

# 验证：枚举出手柄（应看到 "Generic X-Box pad" 或类似名字）
adb shell "cat /sys/class/input/input*/name"

# 查 xpad 是否绑定 + 拿到哪个 event 节点
adb shell "cat /proc/bus/input/devices | grep -A 4 -i xpad"

# 若切不过去，查当前 USB 角色
adb shell "cat /sys/class/typec/port0/data_role"
```

> 09-06 实测：当前固件 OTG host 模式下 2.4G 收发器 + hub 枚举正常，
> xpad 驱动绑定成功（event 节点以实际枚举为准）。
> FF 内核支持已随 09-06 固件就位（/proc/config.gz 确认 CONFIG_JOYSTICK_XPAD_FF=y），
> 不需要再刷 FF 内核——插上即有震动能力。

### 7. 切 OTG host 模式（实测有效版，2026-09-07）

> ⚠️ 上面第 6 节的老方法（`echo host > /sys/class/typec/port0/data_role`）**实测无效**：
> 本固件充电栈残缺，typec 角色切换被静默忽略（写入后 data_role 仍停在 device，
> ssusb mode 仍为 peripheral）。**用下面的强制方法**。

```bash
# ① 前置：先连好 WiFi adb（切 host 后 USB adb 通道会断，WiFi 通道不受影响）
#    WiFi 流程见上面第 5 节；板子 WiFi 为「Duck_5G」/ 2.4G「Duck」
#    连接命令（SSID 用英文，密码 00000000）：
adb shell cmd wifi connect-network Duck wpa2 00000000
adb tcpip 5555
adb connect 192.168.31.xxx:5555     # IP 以 ip addr show wlan0 实际为准

# ② 切 root（typec/ssusb 节点 root 才有权限）
adb -s 192.168.31.xxx:5555 root

# ③ 强制切 host（绕开 CC/UCSI，直接写 dwc3 控制器模式）
adb -s 192.168.31.xxx:5555 shell "echo host > /sys/bus/platform/devices/a600000.ssusb/mode"

# ④ 验证（3 秒后）：
adb -s 192.168.31.xxx:5555 shell "cat /sys/bus/platform/devices/a600000.ssusb/mode"   # 应为 host
adb -s 192.168.31.xxx:5555 shell "ls /sys/bus/usb/devices/"    # 应出现 usb1/usb2 根 hub + 1-1.x 子设备

# ⑤ 确认手柄收发器（Razer 1532:0a3f）枚举 + xpad 绑定 + event 节点
adb -s 192.168.31.xxx:5555 shell "cat /sys/bus/usb/devices/1-1.1/idVendor; cat /sys/bus/usb/devices/1-1.1/idProduct"
adb -s 192.168.31.xxx:5555 shell "cat /proc/bus/input/devices | grep -A 4 -i xpad"
# 预期：VID/PID = 1532/0a3f，Name="Generic X-Box pad"，FF=xxx 非零（有震动能力）
```

> 09-07 实测链路：带电源 Hub（VL817 2109:2817）→ 雷云收发器（1532:0a3f）→
> xpad 绑定 `Generic X-Box pad`（input6/event5，FF 能力位在）。
> 铁律：**收发器必须手柄开机才握手**——手柄关机时插，hub 连 connect 事件都不报。
> 恢复默认（回 device 模式）：`echo device > /sys/bus/platform/devices/a600000.ssusb/mode`。
