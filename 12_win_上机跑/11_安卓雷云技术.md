## ⭐ 1. 零基础导览：安卓这头在干嘛（先看这篇）

> 算法（FFT、门限、压缩、增益；**频率只当筛子，振幅才给马达**）和 Windows **同一套**。
> 白话在 `10` 的「零基础导览」。**这一章只补安卓壳**：谁在出声、谁在偷听、谁在写手柄。

### ① 一句话总览

**掌机正在播放的游戏/音乐，被我们偷听 → 拆出 30–130Hz 低音有多重 → 换算成左右马达转速 → 外接手柄跟着震。**

这就是 Windows 上已经做完的 HapticX（雷云复刻），搬到 SNM970/OK700（高通 QCS8550，开发代号 **kalama**，Android 15）。

```
Windows 负责「调参」  —— 人机工程、四档手感、analyzer.py（已完成）
安卓   负责「执行」  —— 同一套菜谱，Kotlin 逐行移植，再接本机采集和手柄
```

**它不是**系统自带的机身震动游戏，也不是雷蛇原版雷云。它是我们自己的 App + 一条开机小桥。

现役版本：**0.1.17**。

### ② 声音怎么走到手柄上（流水线）

每 20 毫秒滚一圈，和 Windows 同一节奏（960 点 @ 48kHz）：

```
游戏 / 音乐 App 出声
        │
        ├─ 听：蓝牙 A2DP 音箱（SRS-XB10）     ← 玩家耳朵
        │     本机喇叭 / 3.5mm 是死的，出声必须走蓝牙
        │
        └─ 偷听：AudioPlaybackCapture          ←【耳朵】
              点一次「开始捕获」（系统弹窗）
              20ms 一块 PCM
                    ↓
              FFT 只留 30–130Hz 贝司           ←【大脑】
                    ↓
              门限 → 压缩 → 左右马达 0~1        ←【翻译官】
                    ↓
              logcat  打一行  HapticXOut: L=… R=…
                    ↓
              root 小程序 ff_bridge 读日志
                    ↓ 写 /dev/input/eventN
              手柄左右马达物理转               ←【肌肉】
```

四个角色对照 Windows（`10` 里那四个）：

| 角色 | Windows | 安卓现役 |
|------|---------|----------|
| 耳朵 | WASAPI 环回，程序直接偷，0 权限 | **AudioPlaybackCapture**（要屏幕/音频授权） |
| 大脑 | `analyzer.py` | `A2HAnalyzer.kt`（同配方） |
| 翻译 | 门限 0.03 / gamma 3 / 增益 0.67 | 相同；安卓采到的低音偏瘦，频段能量再 **×2.5** |
| 肌肉 | `XInputSetState` 0–65535 | `ff_bridge` 写 evdev 的 `FF_RUMBLE` |

旁边几个配角：`HapticXService` 调度（前台服务，免得被系统杀）、主界面四档、游戏上层的悬浮马达条。

### ③ 你熟悉 Linux，安卓多了什么

SNM970 内核是 Linux 6.1。`adb shell` 进去能 `ps`、`ls /dev`、`cat /proc`，**内核这层和服务器没本质差别**。难的是上面那一层「安卓用户态」：谁能录音、谁能出声、谁能写手柄，都不是 `sudo` 开个设备节点就完事。

先记这张对照，后面所有坑都从这儿长出来：

```
你熟悉的 Linux 发行版              这台安卓掌机
─────────────────────────         ─────────────────────────
一个 rootfs（/）                    拆成好几块镜像再拼起来
  /usr  发行版自己编                system      = 「谷歌 + 高通框架」
  /opt  厂家闭源包                  vendor      = 「高通 + 我们板级」
  /home 用户数据                    userdata    = App 数据、你装的游戏
一个 uid=0 就能开声卡               普通 App 是 u0_a41，开不了 /dev/snd
PulseAudio / ALSA 直接录放          必须绕 AudioFlinger（系统音频管家）
chmod 666 /dev/input/event5         还有 SELinux，chmod 往往不够
.deb / 自己编个二进制就能跑         App 要签名；进 /system 还得 platform 钥匙
systemd 管开机                      init.rc / .rc 脚本管开机
journalctl / dmesg                  logcat（用户态）+ dmesg（内核）
```

为什么安卓要多这一层？因为手机/掌机上**每个游戏是不信任的租户**。不能让模拟器直接 `open("/dev/snd/pcmC0D0p")`，否则它能录麦克风、抢喇叭、读别的游戏。谷歌的办法是：所有声音只跟一个管家说话，管家再去碰硬件。

### ④ 为什么不能「开个声卡就录」

Linux 上常见：`arecord -D hw:0,0` 对着声卡。安卓把声卡藏在 **HAL**（Hardware Abstraction Layer，对驱动的一层 C++ 包装）后面。App **不许** 碰 ALSA。只能跟 **AudioFlinger**（进程名 `audioserver`）申请「我要出声」或「我要偷听」。

```
游戏 App ──「我要出声」──► AudioFlinger（混音管家）
                                │
                    ┌───────────┼───────────┐
                    ▼           ▼           ▼
               本机喇叭      蓝牙音箱     「偷听口」
               (SPEAKER)     (A2DP)    (给我们用的捕获)
                    │           │
                    ▼           ▼
                 本板死了     现役活路
```

本机喇叭这条 HAL 的 `write()` **会永久卡住**（固件 bug，不是我们写坏的）。所以：

| 你想做的事 | 不能走 | 必须走 |
|------------|--------|--------|
| 玩家听见游戏 | 本机喇叭 / 3.5mm | **蓝牙 A2DP**（另一条 HAL，不经过坏喇叭） |
| 我们分析低音 | 去读喇叭、去读 ALSA | **PlaybackCapture**（管家把正在播的 PCM 另抄一份） |

这就是「听」和「偷听」为什么是**两条线**。Windows 的 WASAPI 环回是一条线同时干完；安卓被这台板的喇叭 bug 拆开了。

再补三个容易混的词：

- **PCM** = 没压缩的波形（一串振幅数字）。我们的 FFT 只能吃这个。
- **offload** = 「解码别占 CPU，扔给芯片/蓝牙芯片自己解」。结果 CPU 上看不到 PCM，偷听口是空的。所以固件里写了 `a2dp_offload.disabled=true`，强迫走软件栈。
- **PAL** = 高通自己那层音频 HAL。本板上 **PCM 走 PAL 去 A2DP 会挂死**；压缩流（AAC）有时能过。现役不走那条。

### ⑤ 两棵源码树、两块镜像（QSSI / Vendor）

高通 Android 15 把「能换的安卓」和「板子定制」拆开编，像发行版把 `/usr` 和 `/opt` 分开打包：

| 树 | 路径（编译机 VM） | 编出来主要进谁 | 我们放了什么 |
|----|-------------------|----------------|--------------|
| **QSSI** | `LA.QSSI.15.0` | `system`（框架、系统 App） | HapticX.apk（priv-app） |
| **VENDOR** | `LA.VENDOR.15.4.3` | `vendor`（驱动、音频策略、开机脚本） | A2DP 策略、`ff_bridge`、关 offload |

`SNM970_A15_build.sh` **每次先编 QSSI 再编 vendor**。只 `make` 半边，雷云会漏一半。内核又是**第三摊**（`kernel_platform`）：改驱动 / 设备树才要删 `Image`；这次雷云没改内核，**不要删 Image**。

刷机包把这几块拼进一个 `super` 分区。你在板上 `ls /system`、`ls /vendor` 看到的，就是这两棵树分别编出来的。

### ⑥ App 不是一个普通 Linux 进程

Linux 上你写个 C 程序、`chmod +x`、root 跑，就能开 `/dev`。安卓 App 不是这样：

- 安装包叫 **APK**（就是个 zip：代码 + 资源 + 一张「我想要什么权限」的清单）。
- 每个 App 一个 **UID**（我们是 `u0_a41`）。像 Linux 每个用户一个 uid，但更狠：默认打不开别人的文件，也打不开 `/dev/input`。
- 屏幕上那一页叫 **Activity**（界面）。长期在后台干活必须做成 **Service**。要听声音还得是 **前台服务**（通知栏挂一条），否则系统过一会儿就杀。
- 进 `/system/priv-app` 叫 **priv-app**：权限比应用商店里的 App 大，**仍不是 root**。所以「算强度」在 App 里做，「写手柄」在 root 小程序 `ff_bridge` 里做。
- 覆盖系统里已经预装的 App，APK 必须用编系统那把 **platform 钥匙**签（`platform.pk8`）。自己电脑 Gradle 默认的 debug 钥匙，`adb install -r` 会失败或装成另一个身份。

### ⑦ 权限有三层，别和 chmod 混

Linux 你改权限通常就 `chmod` + 偶尔 AppArmor。安卓叠了三层，**缺一层就不让干**：

| 层 | 像什么 | 我们用到的 |
|----|--------|------------|
| **Manifest** | 安装包里声明「我想要这些能力」 | 前台服务、悬浮窗 |
| **appops** | 运行时开关，`adb` 可拨 | `PROJECT_MEDIA allow` = 准偷听别的 App 的声音 |
| **SELinux** | 内核强制标签，chmod 救不了 | `ff_bridge` 现在挂在 `u:r:su:s0`，所以只要 **userdebug** 固件 |

用户点「开始捕获」弹出来的，是 **MediaProjection**（屏幕/音频共享对话框）。这是安卓隐私框，**刷机预装也消不掉第一次**，Linux 没有对应物。它不是「麦克风权限」，也不是 `RECORD_AUDIO`。

`user` 包 = 给用户的正式固件，adb 不能 root。`userdebug` = 能 `adb root` 的调试固件。我们的桥目前绑在 `su` 域上，**user 包起不来**。

### ⑧ 你会的 Linux 命令，安卓怎么写

| 你想做的 | Linux 习惯 | 这台上 |
|----------|------------|--------|
| 进壳 | ssh | `adb shell`（WiFi：`adb connect 192.168.x.x:5555`） |
| 看进程 | `ps aux` | `ps -A` 或 `pidof ff_bridge` |
| 看用户态日志 | `journalctl -f` | `adb logcat -s HapticXOut:V` |
| 看内核日志 | `dmesg` | 还是 `dmesg`（手柄枚举看这个） |
| 看某个服务状态 | `systemctl status` | `dumpsys media.audio_flinger` / `dumpsys package com.meig.hapticx` |
| 装软件 | `dpkg -i` | `adb install -r xxx.apk`（系统预装还得 platform 签） |
| 杀我们的 App | `kill` | `am force-stop com.meig.hapticx` |
| 拨运行时权限 | （没有） | `appops set com.meig.hapticx PROJECT_MEDIA allow` |
| 看属性（有点像 sysctl） | `/proc/sys` | `getprop persist.bluetooth.a2dp_offload.disabled` |
| 手柄节点 | `/dev/input/event*` | 一样；**先 grep 名字再写，别写到板载震子** |

### ⑨ 五个常见误会（先打预防针）

| 误会 | 实际 |
|------|------|
| 给了麦克风权限就能偷听游戏 | 麦克风是 `RECORD_AUDIO`。偷系统声要 **MediaProjection + PROJECT_MEDIA** |
| `dumpsys` 里看到很多音轨 = 喇叭在响 | 本板喇叭 HAL 会卡死：轨堆满、**0 次 write**。要看 `Total writes` / `Blocked` |
| OnionKnight 首页没有图标 = 没装上 | 它故意不列 sideload。用 `am start` 或系统桌面 |
| `/dev/input/event5` 永远是手柄 | 插拔一次编号就变。板载 `qcom-hv-haptics` 也宣称能震 |
| `chmod 666` 手柄节点，App 就能写 | SELinux 拦。必须走 `ff_bridge` |

## 2. 关键名词对照表（看到不懂的回来查）

算法词（**FFT / 门限 / 压缩 / 增益 / ERM / LRA / A2H / 包络 / 谱通量**）看 `10` 第 ⑥ 节，两端共用，这里不重复。下面只补 **安卓 / 本板** 才会碰到的。

### 音频栈（听 / 偷听）

| 名词 | 白话（按 Linux 人的习惯说） |
|------|------------------------------|
| **AudioFlinger / audioserver** | 系统里唯一的混音 daemon。App 不碰 ALSA，只跟它申请出声或偷听 |
| **AudioTrack** | App「我要出声」时拿到的那根笔。往里面 `write` PCM，管家再去混 |
| **AudioRecord** | App「我要录音」时拿到的话筒。我们**不用**它录麦克风 |
| **HAL** | 对底层驱动的包装。喇叭 HAL 在这台板上是死的；蓝牙 HAL 是活的 |
| **PAL** | 高通自己的音频 HAL。PCM 走它去 A2DP 会挂；压缩流有时能过 |
| **PCM** | 未压缩波形。FFT 的口粮。offload 之后你往往只看得到压缩包，看不到它 |
| **A2DP** | 蓝牙「听音乐」通道，完整立体声。玩家听声走这里 |
| **HFP** | 蓝牙「打电话」通道，单声道、烂。音箱只挂 HFP = 听起来像没连上媒体 |
| **offload** | 解码扔给芯片。CPU 看不到 PCM。必须关掉，我们才能偷到波形 |
| **AudioPlaybackCapture** | 官方「偷听正在播放的 App」API。类似 WASAPI 环回，但要授权，且游戏可拒绝 |
| **REMOTE_SUBMIX** | 另一条「镜像轨」老路。本板经常建了又拆、peak=0，**不要当成功** |
| **MediaProjection** | 「开始捕获」那个系统弹窗。授权的是「共享屏幕/音频」，不是麦克风 |
| **audio_policy** | 管家的路由表（XML）：这段声音该去喇叭还是蓝牙。我们改过两份 |

### 权限 / 签名 / 进程

| 名词 | 白话 |
|------|------|
| **APK** | 安卓安装包（zip）。代码 + 界面 + Manifest |
| **Activity** | 一屏界面。切走游戏后，它可能被挡住，所以才要悬浮条 |
| **Service / 前台服务** | 没界面的长期任务。通知栏挂着，系统才不杀 |
| **UID / u0_a41** | 每个 App 一个用户。沙箱，不是 root |
| **Manifest** | 安装包里「我想要这些能力」的声明 |
| **appops** | 运行时开关。`PROJECT_MEDIA` = 准不准偷听别的 App |
| **priv-app** | `/system/priv-app` 里的系统级 App，比商店 App 权限大，仍不是 root |
| **platform 签名** | 编 AOSP 用的钥匙（`platform.pk8`）。预装 App 要用同一把才能覆盖 |
| **userdebug / user** | 调试固件（能 adb root）/ 正式用户包。桥目前只活在 userdebug |
| **SELinux 域** | 内核标签。`u:r:su:s0` 是 root 调试域；chmod 改不掉它 |

### 固件怎么编

| 名词 | 白话 |
|------|------|
| **AOSP** | 谷歌公开的安卓源码。高通再叠一层 |
| **QSSI** | 高通「可换的 system」。我们的 APK 编进这里 |
| **vendor** | 板级：驱动、音频策略、开机脚本。桥编进这里 |
| **kalama** | QCS8550 这颗 SoC 的开发代号。`lunch kalama-userdebug` |
| **Soong / Android.bp** | 安卓自己的构建（替代一部分 Make）。ELF 预置必须走它 |
| **PRODUCT_COPY_FILES** | 旧 Make 语法「拷个文件进镜像」。Android 15 **不许用它拷 ELF** |
| **cc_prebuilt_binary** | 正确的「把编好的 C 程序放进 vendor」写法 |
| **Image（内核）** | `device/qcom/kalama-kernel/Image`。改内核/设备树才删；这次雷云别删 |

### 手柄 / 输出

| 名词 | 白话 |
|------|------|
| **evdev / eventN** | Linux 输入设备节点。和桌面 Linux 相同 |
| **FF / FF_RUMBLE / EVIOCSFF** | Linux 力反馈。Windows 的 `XInputSetState` 到安卓就变成写这个 |
| **xone** | 开源 Xbox One / GIP 驱动。本板自带 xpad 握手不全，震不稳 |
| **GIP** | Xbox 新协议。雷蛇收发器 1532:0a3f 走这个，不是老 xpad 的 360 模式 |
| **xpad** | 内核里老的 Xbox 360 驱动。这只手柄不会稳在它熟悉的 PID `0a4c` |
| **qcom-hv-haptics** | **板载**震子，也宣称 `FF_RUMBLE`。发错节点 = 机身抖、手柄不抖 |
| **logcat** | 安卓用户态日志。App 打 `HapticXOut: L=0.3 R=0.2`，桥去读 |
| **ff_bridge** | 我们写的 root 小程序：读 logcat → 写 evdev。App 自己写不了节点 |
| **悬浮窗** | `TYPE_APPLICATION_OVERLAY`，像桌面 always-on-top。游戏全屏也能看见马达条 |
| **OnionKnight** | 掌机游戏前端。它**不列出**你 sideload 的图标，不等于没装上 |

### 调试时会看到的

| 名词 | 白话 |
|------|------|
| **dumpsys** | 问某个系统服务「你现在什么状态」。音频看 `media.audio_flinger` |
| **getprop / setprop** | 安卓属性，有点像持久化的 sysctl。offload 开关在这里 |
| **am** | Activity Manager 命令行。`am start` 开 App，`am force-stop` 杀 App |
| **sideload** | 不经过商店、`adb install` 或拷 APK 装上去 |
| **peak** | 一块 PCM 里振幅最大值。0 = 偷到的是静音（管线可能是空的） |

## 3. 和 Windows 比，一样在哪、差在哪

**一句话：翻译层已经同一套数字；听和演奏，安卓多绕了两步。**

| 层面 | Windows | 安卓 | 状态 |
|------|---------|------|------|
| ① 参数配方 | 均衡 = 雷云日志真值 | 四档预设与 Win 相同 | ✅ 对齐 |
| ② 算法 | `analyzer.py` | `A2HAnalyzer.kt` | ✅ 对齐。安卓只多 `CAPTURE_SCALE=2.5`（PlaybackCapture 的 30–130Hz 比 WASAPI 瘦） |
| ③ 听声 | WASAPI 环回 | 必须 A2DP 出声 + 官方捕获 API | ⚠️ 本机喇叭/3.5mm 死；部分游戏可 opt-out |
| ④ 演奏 | XInput 直达 | App 写不了 evdev，靠 root `ff_bridge` 读日志再 ioctl | ✅ 已通。板载 `qcom-hv-haptics` 也有 FF_RUMBLE，**别发错节点** |
| ⑤ 界面 | 四档 + 频谱 | 四档 + 频谱 + **悬浮条**（游戏全屏也能看） | ✅ |
| ⑥ 硬件天花板 | ERM 只有转速，没有 LRA/扳机 | 同样没有 | ❌ 两端一样 |

Windows 不是「条一直跑满」。左马达跟低音包络，右马达跟节拍脉冲（均衡一拍约 35%，动态约 60%）。安卓 0.1.15/16 曾用整段音量顶马达，看起来一直 100%，**那不是 Windows 算法**，0.1.17 已撤。

仍和原版雷云一样的差距（两端共同）：没有 Interhaptics 多通道乐谱，只有一个强度旋钮拆成左右。细节见 `10`「和雷云比」。

## 4. 现役怎么接起来的

第 1 节讲「为什么要绕」；这里讲「现在接到哪几个文件」。

### 4.1 听：蓝牙先活，再偷听

本机 SPEAKER HAL `write` 永久阻塞，3.5mm 物理不通。出声认 **A2DP**。

固件侧两件事：

- `persist.bluetooth.a2dp_offload.disabled=true`（走软件栈，PCM 才能被抓）
- 两份策略：`audio_policy_configuration.xml`（md5 `7be27531…`）、`bluetooth_qti_hearing_aid_audio_policy_configuration.xml`（md5 `4e472f90…`）

捕获走 **AudioPlaybackCapture**，不要走 REMOTE_SUBMIX（本板镜像轨经常 peak=0）。

`appops set com.meig.hapticx PROJECT_MEDIA allow`。第一次仍要点「开始捕获」（系统 MediaProjection 弹窗没法预装掉）。

### 4.2 拆：Kotlin 移植 analyzer.py

`25_xbox_control/hapticx-android/…/dsp/A2HAnalyzer.kt`

- 48kHz / FFT 50ms / hop 20ms
- 频段 30–130Hz，EQ `0:1, 50:1, 100:0.3, 150:0.3`
- 压缩：`(gated / 0.3) ^ (1/gamma)`
- 瞬态：档位 `transient_vol`（受控 0.25 / 均衡 0.35 / 动态 0.60）
- 左 = body + 0.7×瞬态；右 = 瞬态 + 0.4×body
- 增益 0.67
- 安卓仅有的差：`amp *= 2.5` 再进门限

四档：受控 / 均衡 / 动态 / 自订 + 超低音 / 低音 / 中低音 0–200%。薄低音歌先切 **动态**。公式白话见 `10` 第 ⑤ 节。

### 4.3 震：日志桥，不让 App 直接开 evdev

Linux 上你可能会 `chmod 666 /dev/input/event5` 然后自己的程序 `ioctl`。安卓 App 跑在沙箱 UID 里，节点是 `root:input 660`，**再 chmod 也过不了 SELinux**。所以拆成两段：App 只算数字并打日志（谁都能写 logcat），root 小程序再去开节点。

```
HapticX  LogOutput  →  logcat tag HapticXOut
ff_bridge（root）    →  解析 L= / R=  →  EVIOCSFF + EV_FF
```

停震必须强度 0 **并且** 再 play 一次（`EV_FF=1`），否则手柄会停在最后一档。

手柄：Razer 1532:0a3f，内核 **xone**，节点每次插拔要重 grep：

```bash
grep -E 'Microsoft Xbox' -A6 /proc/bus/input/devices
```

**不要**往 `qcom-hv-haptics` 发，那是板载震子。

禁止 `pkill -f ff_bridge`（会杀到自己）；桥活着时不要 `logcat -c`（桥是挂在 logcat 管道上读的，清空等于掐死它）。

### 4.4 界面：悬浮条

捕获后自动浮一条可拖的左右马达（`SYSTEM_ALERT_WINDOW`）。切到游戏后 HapticX 自己的 Activity 看不见，悬浮条还在。

「采到 xx%」是整段音量，给自己看采没采到；**马达条才是算法输出**。也可最近任务里分屏。

## 5. 怎么用、怎么验

板子 WiFi adb 上次 `192.168.31.228:5555`（重启会变）。App **0.1.17**。

### A. 真声 + 手柄

1. 手柄插着，SRS-XB10 走**媒体**（不是只通话）。
2. 打开 HapticX → **开始捕获**（授权一次）。
3. 放游戏或有鼓点的歌。悬浮条：左随低音、右跟节拍，不是一直 100%。
4. 声停，条回 0，手柄停震。

SSD 园林曲 `GAMES/jade-garden-serenade.mp3` 在均衡可能不震，**动态**应震。

### B. 四档

切 受控 / 均衡 / 动态 / 自订。选中绿字。超低音拖到 0 再放贝司，应明显变弱。

### C. 应急停震

界面「停止」、通知「停止震动」，或划掉任务。

```bash
adb shell am force-stop com.meig.hapticx
adb shell /data/local/tmp/ff_rumble /dev/input/event5 0:0 80 2
```

`eventN` 以当时 grep 为准。
