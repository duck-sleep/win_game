## 一句话

这只手柄在 NS 模式下就是一只「任天堂 Pro 手柄」（USB `057E:2009`）。
HD 振动 = 每只手一个线性马达，主机每 ~20 ms 发一个 64 字节输出报告 `0x10`，
里面左右各 4 字节：**一个高频振荡器（Hz + 振幅）+ 一个低频振荡器（Hz + 振幅）**。
唱歌 = 按音符换 Hz；音频转触觉 = 复用 `25_xbox_control` 已对齐雷云 DLL 的编码器，
把它每 20 ms 吐出的「两条曲线（力度, Hz）」放进这两个振荡器。

和雷云那条线的区别：雷云把 SENSA 比特流（91 字节 Feature 报告 4）交给手柄固件去合成；
NS 这条是主机直接给振荡器的频率和振幅，没有比特流、没有校验和。

## 协议（全部抄自 dekuNukem + SDL，不要改）

### 输出报告（主机 → 手柄），USB 下一律补零到 64 字节再 `dev.write`

| 报告 | 字节 | 用途 |
|------|------|------|
| `80 xx` | `[0x80, cmd, 0…]` | USB 专有命令。`02` 握手，`03` 切高速，`04` 强制只走 USB（不超时回蓝牙），`05` 取消强制 |
| `01` | `[0x01, 计数, 振动 8 字节, 子命令号, 子命令数据…]` | 振动 + 子命令 |
| `10` | `[0x10, 计数, 振动 8 字节]` | 只振动（主循环只用这个） |

- 计数：每发一个 `01`/`10` 报告 +1，在 `0x0–0xF` 里循环（`& 0x0F`）。
- 振动 8 字节：**前 4 字节左马达，后 4 字节右马达**。
- 静止：`00 01 40 40`（= 高频 320 Hz 振幅 0、低频 160 Hz 振幅 0）。

### 输入报告（手柄 → 主机），只在初始化时读

| 报告 | 含义 |
|------|------|
| `81 xx` | `80 xx` 的应答（`80 04` 没有应答，不要等） |
| `21 …` | 子命令应答。`[13] & 0x80` 是 ACK，`[14]` 是子命令号 |
| `30 …` | 全状态（按键/摇杆），握手后约 8 ms 一个。本程序不用，不读也行 |

### 初始化顺序（SDL `BTrySetupUSB` + `SetVibrationEnabled`）

```
80 02  等 81 02（100 ms 超时，最多重试 3 次）
80 03  等 81 03（等不到也继续：SDL 注释说有的兼容手柄不回）
80 02  等 81 02（等不到也继续）
80 04  不等
01 计数 00 01 40 40 00 01 40 40 48 01   等 21 且 [14]==0x48 且 [13]&0x80
```

### 一侧 4 字节怎么编（参考实现，照抄）

频率码：`e = round(log2(Hz / 10) * 32)`。
- 高频振荡器：`hf = (e - 0x60) * 4`，夹到 `0x004–0x1FC`（81.75–1252.57 Hz），9 位。
- 低频振荡器：`lf = e - 0x40`，夹到 `0x01–0x7F`（40.88–626.29 Hz），7 位。
- 精度：1/32 八度 ≈ 37.5 音分一档，最大误差 ±18.75 音分。

振幅档 `i`（0–100，就是 dekuNukem 振幅表第 i 行，`HA = 2i`）：
- `amp > 0.23`：`i = round(log2(amp*8.7)*32)`
- `0.12 < amp ≤ 0.23`：`i = round(log2(amp*17)*16)`
- `0 < amp ≤ 0.12`：表里 i=2…15 每档 ×2^(1/4)，`i = max(1, round(15 + 4*log2(amp/0.112491)))`
- 最后夹到 `0–100`。

字节：高频振幅 `= 2i`；低频振幅 16 位 `= ((i & 1) << 15) | (0x40 + (i >> 1))`
（奇数档那一位要进第 2 字节的 `0x80`，**dekuNukem 示例公式 `encoded/2+64` 会丢这一位，别抄那个**）。

```python
import math

NEUTRAL = bytes([0x00, 0x01, 0x40, 0x40])
AMP_MAX_INDEX = 100


def amp_index(amp: float) -> int:
    if amp <= 0.0:
        return 0
    amp = min(amp, 1.0)
    if amp > 0.23:
        i = round(math.log2(amp * 8.7) * 32.0)
    elif amp > 0.12:
        i = round(math.log2(amp * 17.0) * 16.0)
    else:
        i = max(1, round(15 + 4 * math.log2(amp / 0.112491)))
    return max(0, min(AMP_MAX_INDEX, int(i)))


def freq_code(hz: float) -> int:
    hz = min(max(hz, 1.0), 1252.0)
    return int(round(math.log2(hz / 10.0) * 32.0))


def encode_side(hf_hz: float, hf_amp: float, lf_hz: float, lf_amp: float) -> bytes:
    ih, il = amp_index(hf_amp), amp_index(lf_amp)
    if ih == 0 and il == 0:
        return NEUTRAL
    hf = max(0x004, min(0x1FC, (freq_code(hf_hz) - 0x60) * 4))
    lf = max(0x01, min(0x7F, freq_code(lf_hz) - 0x40))
    lf_amp16 = ((il & 1) << 15) | (0x40 + (il >> 1))
    return bytes([
        hf & 0xFF,
        (ih * 2) | ((hf >> 8) & 0x01),
        lf | ((lf_amp16 >> 8) & 0x80),
        lf_amp16 & 0xFF,
    ])
```

- 主循环一直发 `0x10`，**哪怕没声音也发静止**（SDL：长振动要 ≤50 ms 刷新一次，否则马达会停）。

### N6 [x] 模型：雷云曲线 → NS 振荡器映射 + 瞬态去重（不需要手柄）

**这是设计，不是抄来的。** 雷云手柄收的是两条曲线 + 瞬态，由它的固件合成；
NS 只给两个振荡器。默认映射如下，靠 N7 用户手感再调：

| 雷云编码器输出（每只手） | NS 这只手 |
|------|------|
| 曲线 0（30–100 Hz 带）`(力度 a0, Hz h0)` | 低频振荡器：`lf_hz = h0`，`lf_amp = a0` |
| 曲线 1（100–200 Hz 带）`(力度 a1, Hz h1)` | 高频振荡器：`hf_hz = h1`，`hf_amp = a1` |
| 瞬态（新出现的） | 高频振荡器临时改成 `TRANSIENT_HZ = 160`、振幅 `max(a1, 瞬态力度)`，持续 `TRANSIENT_PACKETS = 2` 个包 |

- Hz 越界由 `encode_side` 自己夹（低频最低 40.88，高频最低 81.75），映射层不要再夹。
- 曲线少于 2 条时缺的当 `(0.0, 0.0)`。
- 瞬态的 `pitch` 字段**不是 Hz**（编码器里固定 0.5），不要用它。160 Hz 是设计值（Pro 手柄静止包里低频默认 160 Hz）。

**瞬态去重（必须做）**：编码器每块都把最近 6000 个样本（125 ms）重扫一遍，同一下敲击会在连续好几块里重复出现。
用绝对样本号去重：

```python
# 每块 process_block 之后：
total += blk.shape[0]                 # 累计喂进去的帧数
hist = len(enc._raw_l)                # 编码器历史长度（满了是 6000）
for tr in part.transients:            # 每只手各自一套 last_abs
    abs_i = total - hist + int(round(tr.time * sample_rate))
    if abs_i - last_abs[hand] > int(0.022 * sample_rate):
        触发一次（剩余包数 = TRANSIENT_PACKETS，力度 = tr.amp）
        last_abs[hand] = abs_i
```

`tr.time` 是窗口里的秒数，`enc._raw_l` 是私有属性。这里只读不改，注释写明依赖它。

已知局限（DLL 本身的行为，不是 bug，照实写进 README）：每只手只有 2 个瞬态槽，新的必须比旧的**更响**才会替换。
所以一串等响的敲击里，后面的要等前面的滑出 125 ms 窗口才出现，**最多晚约 100 ms**。

- 做 `ns_rumble\a2h_map.py`：一个类 `A2HToNS`，`__init__(sample_rate)`，
  `frame_to_bytes(frame, total_samples, hist_len) -> (left4, right4)`，内部维护每只手的 `last_abs`、剩余瞬态包数。

### N7 [ ] 模型 + 用户：实时音频转振动

```python
cap = WasapiLoopback(); cap.open()            # 默认播放设备，20 ms 一块
enc = A2HEncoder(gain=1.0)                     # 编码器里不乘增益
mapper = A2HToNS(cap.sample_rate)

try:
```
